# PR 2 — Group Rooms: Client & Synchronization

При новой ревизии старая загрузка могла задерживать применение актуального
состояния, а изменение роли без новой ревизии не меняло ключ обработки плеера.
Теперь ревизия, роль и поколение/статус подключения отменяют устаревшую операцию;
состав участников и чужие отчёты не вызывают повторное применение состояния.
Каждый слушатель синхронизируется с общей RoomState и отправляет свой отчёт.

Агент публикует `participants`, `selfParticipantId` и `capacity`, сохраняя
статусы и ошибки старого UI. Публичные GUID не выводятся из токенов или индексов.
Опрос, RTT-оценка, пороги коррекции и защита от неверных ID сохранены.

## Граница готовности и зависимость

Это независимая клиентская часть, готовая к сочетанию с PR 1. В текущей базе
остаётся серверный протокол v1 на два места: `participants` пуст,
`selfParticipantId` равен null, вместимость равна 2. Полноценный групповой
транспорт ещё не подключён. Сервер, DTO протокола, Electron UI и установщик
не меняются.

После PR 1 нужно заменить один адаптер RoomMembership, обновить конструкторы
RoomView в новых фикстурах и проверить настоящий сервер с десятью подключениями.
Точный код адаптера и шаги совмещения находятся в
[GROUP_ROOMS_SYNC.md](GROUP_ROOMS_SYNC.md). Адаптер отдельно компилируется с
текущими DTO рабочего дерева PR 1. Политика передачи роли в группе зависит от
работы над управлением ролями; здесь проверяется реакция плеера на смену роли.
