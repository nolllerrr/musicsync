# Клиент и синхронизация групповых комнат

`RoomConnection` использует протокол v2 из [GROUP_ROOMS_PROTOCOL.md](GROUP_ROOMS_PROTOCOL.md). `RoomMembership` переносит реальные `participants`, `capacity` и собственный ID из welcome в `ConnectionView`. Пустой адаптер v1 заменён. Клиент, агент и сервер используют общий `Participant`; временный файл с образцом адаптера удалён.

`RoomPlayer` получает `IRoomConnection`. Каждый экземпляр читает общий `RoomState`, собственную роль, поколение соединения и свои часы, отправляет независимый отчёт. Отчёты слушателей не управляют чужими плеерами. Для ожидания следующей песни допускается длительность из отчёта ведущего.

Ключ применения: `(generation, revision, role, retry)`. Состав, порядок участников и их отчёты этот ключ не меняют. Событие `Changed` отменяет текущую операцию при смене ревизии, роли, поколения или статуса соединения. После уже переданной команды проверяется актуальность: отмена не откатывает выполненную команду, но запрещает следующие шаги и успешный отчёт старой операции. AgentPipe передаёт `cancelEvaluation`, Sonata проверяет актуальность перед мутацией.

После загрузки позиция пересчитывается по серверным часам. Порог коррекции — 1200 мс, интервал повторной коррекции — 8 секунд. Слушатель ждёт следующую песню ведущего у конца трека и безопасно останавливает известный трек при потере идентичности. Неисправный или медленно загружающий слушатель не блокирует остальных. При новой ревизии или ручном повторе синхронизация возобновляется.

Частоты: опрос плеера 450 мс в комнате / 900 мс без комнаты; ping каждые 2 секунды; отчёт устойчивого воспроизведения каждые 2 секунды; агент публикует изменившееся состояние каждые 250 мс. Сервер объединяет отчёты отдельно, раз в 250 мс на комнату. Переподключение использует backoff 1/2/4/8 секунд; серверные `error`/`ended` завершают сессию.

При возврате ведущего с прежней ревизией его локальные изменения во время обрыва сохраняются и затем публикуются. После подтверждённой передачи роли прежний ведущий применяет общую комнату как слушатель. Незавершённые загрузки и перемотки проверяются на смену роли и ревизии.

## Состояние агента

Одна JSON-строка `type: state` через AgentPipe:

| Поле | Значение |
|---|---|
| `status` | idle / connecting / connected / reconnecting / ended |
| `role`, `code` | Собственная роль и код комнаты |
| `participants` | Массив публичных Participant с независимыми отчётами |
| `selfParticipantId`, `capacity` | Собственное место и вместимость |
| `peerConnected` | Совместимость: подключён хотя бы один другой участник |
| `supportsLeadershipTransfer` | Согласовано расширение адресной передачи |
| `transfer` | id, initiatorParticipantId, targetParticipantId, remainingMs; только при connected |
| `swap` | Прежний парный запрос для совместимости |
| `error`, `playbackError` | Машинные коды сетевой/локальной ошибки |

При reconnecting последний состав сохраняется, но UI показывает неопределённый статус других участников. Согласие на передачу во время обрыва не показывается. При ended/idle состав, ID, вместимость и запрос очищаются. Секретные токены в IPC отсутствуют.

Команды Electron → агент: `transferLeadership` с `targetParticipantId`, `acceptLeadership`/`cancelLeadership` с `transferId`. Preload экспортирует только эти узкие операции; main проверяет доверенный главный фрейм и GUID перед передачей. Сервер проверяет полномочия независимо от UI.

Автоматические проверки включают детерминированную группу из 10 плееров, настоящий Kestrel с 10 RoomConnection/RoomPlayer, медленную загрузку, ошибку трека, Play/Pause, перемотку, новый трек, передачу роли во время загрузки/перемотки и восстановление. Ручная проверка реальной Sonata и аудиорасхождения остаётся обязательной: [TESTING.md](TESTING.md).
