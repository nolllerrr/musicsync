# Поддержка обновлённой Яндекс Музыки

Состояние после уточнения требований 13 ноября 2026 года.

## Поведение патчера

Исходный XAML интерфейса восстановлен без изменений относительно `codex/group-rooms-integration`. Нет карточки совместимости, кнопки восстановления, новых настроек, внешнего восстановителя и заданий Планировщика. Проверка при открытии выполняется асинхронно, только читает файлы и сообщает о проблемах через существующий `Notice`. Исправные поддерживаемые установки не получают дополнительных сообщений. Запоздавшая проверка не заменяет сообщения о нажатой пользователем операции.

Поддерживаются точные сборки 5.126.1 и обнаруженная 5.127.0 (ProductVersion 5.127.0.0). Проверки версий, исходных SHA-256, ASAR integrity и ресурса ElectronAsar сохранены. [Исходные hashes и аудит](YANDEX-UPDATE-AUDIT.md).

После официального обновления пользователь нажимает обычную кнопку «Установить патч». Проверенные новые оригиналы получают собственные backups. Старый журнал и payload архивируются без восстановления прежней версии поверх новой. Endpoint сохраняется, в том числе при обрывах подготовки/очистки. Снятие патча возвращает точные оригиналы соответствующей сборки. Неизвестные пары и перенаправленные пути не разрешаются.

CLI сохраняет команды `install`, `uninstall` и read-only `diagnose [каталог]`. Команды фонового восстановления удалены. На рабочем ПК подтверждены отсутствие задания `MusicSync-Recovery-*` и выключенная прежняя регистрация; настройки пользователя не менялись.

## Проверки

После удаления механизма автоматической переустановки проходят 195 .NET-тестов: 76 установщика, 116 Core/Server и 3 Agent, без ошибок и пропусков. Release собирается с `-warnaserror`, `dotnet format --verify-no-changes` проходит. Тесты установщика проверяют обе версии, неизвестные hashes, update/reinstall, старые и прерванные журналы, архивный endpoint, rollback, блокировки, отказ доступа, символические ссылки/junction и барьер запуска EXE во время ручной транзакции. Прежние 21 тест Планировщика/восстановителя удалены вместе с этим компонентом.

Проверки на отдельных настоящих копиях 5.126.1/5.127.0 и пределы runtime-проверок описаны в аудите. Групповые комнаты сохранены: база ветки — `codex/group-rooms-integration`, её Electron scripts и `src` не изменены.

После возврата исходного UI пересобран `dist/MusicSync-Together-0.1.10-Windows-x64.exe`, SHA-256 `58F8F4B9A6179816FB9FF385A2B32C151EAA67E6CED28A326504A2EA3A7F18B6`. На отдельной настоящей копии 5.127.0 повторены install/uninstall новым EXE: обе команды успешны, исходные SHA-256 EXE/ASAR восстановлены точно. Рабочая установка не изменялась.

## Предлагаемая автоматизация подготовки новых версий

Это отдельная задача разработки, не фоновая установка на ПК пользователя. Конвейер пока не добавлен и не включён.

1. Обнаружить новую официальную Windows x64 сборку через канал, указанный официальным обновлятором.
2. Скачать её в изолированную среду, проверить происхождение и целостность, извлечь файлы без изменения пользовательской установки.
3. Сравнить package/index/preload, ASAR integrity, PE resource и известные контракты Electron/bridge/Sonata.
4. На отдельной копии проверить patch/unpatch с точным возвратом исходных hashes, запуск и доступные runtime smoke checks.
5. Подготовить изменение каталога поддерживаемых сборок, результаты проверок и сборку патчера в draft PR. Структурный успех сам по себе не разрешает новую сборку конечным пользователям.
6. Если контракты изменились или тесты не прошли, остановиться и описать нужную ручную адаптацию. Авторизованное воспроизведение/комнаты остаются частью приёмки.
7. После проверки и обычного выпуска пользователь получает новый установщик через уже существующую кнопку обновления MusicSync и сам запускает установку патча.

Автоматизация подготавливает поддержку новой версии; она не может гарантированно исправлять произвольные изменения API Яндекс Музыки без адаптации кода. Альтернатива с загрузкой каталога уже проверенных сборок в существующий EXE требует отдельного подписанного канала доверия и пока не реализована.
