# Проверка MusicSync на ПК и ноутбуке

Нужны два компьютера Windows x64 в одной доверенной локальной сети. На каждом проверьте, что в официальной Яндекс Музыке доступна тестовая песня. Используйте клиент и сервер одной версии. Для сборки из исходников запустите `.\scripts\Publish-Windows.ps1` из корня проекта. Архив клиента и папка сервера появятся в `dist/`. Portable-клиент содержит среду .NET.

## Запуск проверки Sonata

Распакуйте архив `MusicSync-<версия>-Windows-x64-portable.zip` целиком на каждом ПК. Завершите работающий MusicSync через пункт **Завершить MusicSync** в трее и откройте `Start-Sonata.cmd` в распакованной папке. Если Яндекс Музыка уже открыта в обычном режиме, завершите её через трей и запустите `Start-Sonata.cmd` ещё раз. В открывшемся окне должна появиться метка **Sonata**.

Тот же запуск можно выполнить вручную из распакованной папки после завершения обоих приложений.

```powershell
$yandex = "$env:LOCALAPPDATA\Programs\YandexMusic\Яндекс Музыка.exe"
Start-Process -FilePath $yandex -ArgumentList '--remote-debugging-address=127.0.0.1', '--remote-debugging-port=9222'
.\MusicSync.Client.exe --sonata-port=9222
```

При обычном запуске EXE клиент выбирает стандартный адаптер. В журнале запуск Sonata отмечается строкой `Player adapter: Sonata (local CDP port 9222).`

Продолжите с шага 1. Пропустите первый пункт шага 2, поскольку клиенты уже запущены. Сверните Яндекс Музыку на ноутбуке. На ПК проверьте ручную смену трека и дождитесь автоперехода в «Моей волне». После проверки завершите Яндекс Музыку из трея и запустите её обычным способом, чтобы закрыть отладочный порт. Для запуска с обычным адаптером уберите `--sonata-port`.

## 1. Запустите сервер на основном ПК

Откройте PowerShell в корне проекта и найдите адрес сетевого интерфейса.

```powershell
Get-NetIPConfiguration | Where-Object IPv4DefaultGateway |
    Select-Object InterfaceAlias, @{n='IPv4';e={$_.IPv4Address.IPAddress}}
```

Выберите IPv4 физического Wi-Fi или Ethernet, через который обе машины подключены к роутеру. Вставьте его в следующую команду. LAN-режим принимает соединения только на указанном частном IPv4 и loopback.

```powershell
$lanIp = Read-Host 'IPv4 основного ПК'
.\dist\MusicSync-Server-Windows-x64\MusicSync.Server.exe --Sync:Mode=Lan --Sync:LanIp=$lanIp --Sync:Port=5050
```

Оставьте это окно открытым и проверьте сервер во втором PowerShell.

```powershell
Invoke-RestMethod http://127.0.0.1:5050/health
```

На ноутбуке проверьте доступность TCP по адресу основного ПК.

```powershell
$lanIp = Read-Host 'IPv4 основного ПК'
Test-NetConnection $lanIp -Port 5050
```

При `TcpTestSucceeded : False` проверьте адрес, общую сеть и изоляцию устройств в гостевой Wi-Fi. Если трафик блокирует Windows Firewall, создайте временное правило для входящего TCP на порт `5050`. Команду выполняйте в PowerShell администратора из корня проекта.

```powershell
$lanIp = Read-Host 'IPv4 основного ПК'
$laptopIp = Read-Host 'IPv4 ноутбука'
$server = (Resolve-Path .\dist\MusicSync-Server-Windows-x64\MusicSync.Server.exe).Path
New-NetFirewallRule -DisplayName 'MusicSync LAN test 5050' -Direction Inbound -Action Allow `
    -Profile Private -Protocol TCP -LocalPort 5050 -Program $server `
    -LocalAddress $lanIp -RemoteAddress $laptopIp
```

После испытания удалите временное правило.

```powershell
Remove-NetFirewallRule -DisplayName 'MusicSync LAN test 5050'
```

## 2. Создайте комнату и подключите ноутбук

1. Для обычного режима распакуйте архив текущей версии целиком. Завершите работающий клиент через меню трея и запустите `MusicSync.Client.exe` из распакованной папки.
2. Ведущий нажимает **Создать комнату**. Адрес сервера для ведущего на ПК по умолчанию — `ws://127.0.0.1:5050/ws`. Передайте автоматически скопированный код слушателю.
3. На ноутбуке слушатель открывает **Настройки подключения**, указывает `ws://<IPv4-основного-ПК>:5050/ws` с фактическим IPv4 ПК и включает **Разрешить ws:// для доверенной локальной сети**. Затем вставляет код в поле **Код комнаты** и нажимает **Подключиться**. Клиент запомнит адрес.
4. После подключения окно показывает код, участников и состояние плеера. Крестик и сворачивание прячут окно в трей, а кнопка **Выйти** завершает участие. Двойной щелчок по значку в трее снова открывает окно.

## 3. Проверьте синхронизацию

1. Ведущий запускает песню прямо в Яндекс Музыке. Для пробы откройте альбом и выберите «Звезда по имени Солнце». Если плеер показывает точный ID текущей записи, слушатель получит ту же песню. MusicSync может всё время оставаться в трее.
2. В Яндекс Музыке ведущий ставит на паузу, перематывает примерно на 1:30 и возобновляет. Проверьте, что слушатель повторил эти действия. Порог автоматической коррекции позиции указан ниже.
3. Ведущий выбирает следующую песню в Яндекс Музыке. Если видите «Точный ID трека недоступен», откройте очередь в Яндекс Музыке или скопируйте ссылку на песню и выберите в трее MusicSync **Запустить ссылку из буфера**. Контрольная ссылка — `https://music.yandex.ru/album/42185896/track/151629851`.
4. На 5–10 секунд отключите сеть только у ноутбука. На ПК поставьте песню на паузу и перемотайте в Яндекс Музыке. После восстановления сети ноутбук должен получить итоговую паузу и позицию. Комната сохраняет место на 90 секунд.
5. Когда оба участника в сети, один нажимает **Сменить роли**, а второй в течение 30 секунд нажимает **Подтвердить смену ролей**. Проверьте, что код комнаты сохранился и новый ведущий управляет паузой и перемоткой.
6. Текущий ведущий выбирает **Выйти из комнаты** в трее. У слушателя статус значка меняется на «Комната закрыта».

Для отдельной проверки автоперехода перемотайте песню у ведущего примерно за пять секунд до конца и дайте ей закончиться. Около конца слушатель ставит локальный плеер на паузу, показывает «ожидание следующего трека ведущего» и продолжает с новой песней ведущего. Между песнями возможна короткая тишина.

Яндекс Музыка должна работать на обоих ПК. При проверке Sonata окно слушателя должно оставаться свёрнутым во время перехода. В обычном режиме MusicSync восстанавливает свёрнутое состояние, если при загрузке нового трека появляется окно.

Для сравнения аудио расположите колонки рядом и послушайте переходы, паузу и удары с чёткой атакой. Для оценки запишите обе колонки одним телефоном с фиксированной позиции. В разделе **Диагностика синхронизации** разница позиций сравнивает показания обоих плееров на общей шкале времени. Фактический выход звука зависит и от аудиоустройств. Значение может отсутствовать, пока у клиентов нет свежих сопоставимых измерений.

## Диагностика

- Кнопка **Открыть журнал диагностики** открывает `%LOCALAPPDATA%\MusicSync\MusicSync.log`. Строки `Revision … applied/corrected in … ms` показывают время от начала применения до наблюдаемого подтверждения. При сбое сохраните ревизию, RTT, позиции, текст ошибки и время.
- Если Windows не отвечает на запрос к плееру, MusicSync пытается прочитать текущий трек и позицию из панели Яндекс Музыки. При сообщении об отсутствии данных откройте альбом в Яндекс Музыке и запустите песню, чтобы была доступна панель с названием и ползунком времени.
- При ошибке запуска проверьте, что окно Яндекс Музыки открыто и песня доступна на этом аккаунте. После этого можно нажать **Повторить синхронизацию**.
- Порог коррекции по умолчанию — 1200 мс. Чтобы изменить его, закройте MusicSync, задайте `correctionThresholdMs` в `%LOCALAPPDATA%\MusicSync\settings.json` и запустите заново. Если пользовательского файла ещё нет, используется `MusicSync.settings.json` рядом с EXE. Диапазон — 500–10000 мс.
- Когда ноутбук будет проверен, завершите сервер через Ctrl+C. LAN-режим рассчитан на доверенную домашнюю сеть. Для удалённого доступа требуется WSS.
