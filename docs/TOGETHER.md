# «Вместе» в Яндекс Музыке

Патч рассчитан на проверенную сборку Яндекс Музыки 5.126.1 для Windows x64. В одном сеансе Windows может работать одна комната MusicSync.

## Установка и настройки

Откройте `MusicSync-Together-0.1.10-Windows-x64.exe`. Введите адрес сервера вида `wss://music.example.net:8443/ws` и нажмите «Установить патч». Если Яндекс Музыка уже запущена, MusicSync закроет её и снова откроет после установки. В боковом меню появится раздел «Вместе».

Кнопка «Сохранить» меняет адрес для следующей комнаты. Для локальной проверки подойдёт `ws://127.0.0.1:5050/ws`. Чтобы вернуть исходные файлы, нажмите «Удалить патч» в том же `.exe`. MusicSync также перезапустит Яндекс Музыку, если она была запущена. Если старый патч был установлен из ZIP, используйте это же окно для смены адреса и удаления.

Кнопка со стрелками в правом нижнем углу проверяет обновления MusicSync. При открытии установщик проверяет последний стабильный релиз на GitHub и показывает жёлтую точку, если есть более новая версия для Windows x64. Нажмите кнопку и подтвердите скачивание, затем запустите новый EXE.

## Сборка и проверка установщика

Соберите автономный Windows x64 `.exe` на компьютере с .NET 10 SDK. Файл появится в `dist`. Параметр `-Endpoint` позволяет задать адрес по умолчанию для первой установки.

```powershell
.\scripts\Publish-Together.ps1
```

Для проверки используйте отдельную копию каталога Яндекс Музыки и запустите её с отдельным профилем. Установщик перезапустит эту копию с тем же профилем.

```powershell
Start-Process -FilePath '.\dist\MusicSync-Together-0.1.10-Windows-x64.exe' -ArgumentList '--directory', 'C:\Test\YandexMusic'
Start-Process -FilePath 'C:\Test\YandexMusic\Яндекс Музыка.exe' -ArgumentList '--user-data-dir=C:\Test\YandexMusicProfile'
# Установите и снимите патч в окне MusicSync. Проверьте перезапуск после каждого действия.
```

Установщик сверяет версию и SHA-256 оригинальных файлов и сохраняет их копии. При удалении он сверяет SHA-256 установленной пары, прежде чем восстановить оригиналы. Обновлённую сборку можно патчить после проверки её версии и контрольных сумм. Патч меняет подписанный `.exe`. При приёмке запустите пропатченную копию и после удаления сверьте SHA-256 обоих файлов с исходными.

Журнал `musicsync-together.log` находится в каталоге профиля Яндекс Музыки. Если запустили тестовую копию с `--user-data-dir`, ищите журнал в указанном каталоге.

### Потеря журнала и внешнее обновление (MS-04)

На Windows запустите `dotnet test .\tests\MusicSync.Patch.Tests -c Release`. Тесты создают ASAR и PE во временных каталогах, имитируют версию Яндекс Музыки 5.126.1 и обходятся без её процессов.

- Если пропал `.musicsync-together`, а пропатченные файлы остались, установка и удаление завершаются отказом.
- Если внешнее обновление заменило оба файла на пару с другими SHA-256, установка и удаление завершаются отказом как при сохранённом, так и при потерянном журнале. Тесты моделируют замену файлов при той же версии EXE.
- Если вернулась точная исходная пара, журнал пропал, а `resources/musicsync-together` остался, удаление сообщает «Патч уже снят», а установка отказывается использовать каталог без журнала. Во всех этих случаях установщик сохраняет содержимое файлов и каталогов.

Ручная проверка на отдельной установке Яндекс Музыки 5.126.1 x64:

1. Направьте установщик в тестовый каталог через `--directory`. Запишите SHA-256 `resources/app.asar` и `Яндекс Музыка.exe` через `Get-FileHash -Algorithm SHA256`. Установите патч, проверьте наличие «Вместе», снимите патч и сравните обе суммы с исходными.
2. Установите патч снова и закройте тестовую Яндекс Музыку. Перенесите `.musicsync-together` за пределы каталога приложения. Попробуйте установить и удалить патч. Ожидайте отказ в обоих случаях и сверьте SHA-256 файлов с состоянием перед попытками.
3. Верните `.musicsync-together` на место. Если на отдельной тестовой установке доступно штатное обновление, выполните его. Запишите версию, наличие каталога резервных копий и новые SHA-256. При замене файлов на неизвестную установщику сборку проверьте, что обе операции отклонены, а суммы обновлённых файлов сохранились.

## Проверка комнаты на двух ПК

На обоих ПК установите патч и укажите один и тот же адрес сервера `wss://…/ws`. [Развёртывание сервера](VPS_DEPLOY.md)

1. В боковом меню убедитесь, что «Вместе» стоит между «Моя волна» и «Для вас и Тренды». Проверьте открытие клавиатурой, закрытие по `Esc`, смену темы и переходы между разделами. После перезагрузки страницы кнопка должна появиться один раз, а комната сохраниться.
2. Создайте комнату на первом ПК, скопируйте код и подключитесь на втором. Сверните окно слушателя. У ведущего выберите трек вне очереди, поставьте его на паузу и перемотайте. Сверьте трек и позицию на обоих ПК.
3. Прервите и восстановите соединение на одном из ПК. После переподключения проверьте, что комната и текущий трек сохранились. Запросите смену ролей и подтвердите её на втором ПК в течение 30 секунд. Проверьте, что новая команда перемотки поступает от нового ведущего.
4. Проверьте автопереход на следующий трек и убедитесь, что слушатель получает новую песню ведущего. Ведущий нажимает «Выйти». У слушателя комната должна закрыться.

## Групповой интерфейс «Вместе»

Панель поддерживает состав до 10 участников: код с копированием, число участников и вместимость,
состояние соединения и список с ролями. Ведущий отмечен подчёркнутой ролью, текущий пользователь —
именем «Вы» и фоном строки. Остальные получают временные имена «Участник 2», «Участник 3» и т. д.
Это обозначения внутри комнаты, а не имена аккаунтов. Они сохраняются при обновлениях состава
и сбрасываются при выходе или смене комнаты. Список прокручивается отдельно, вся панель ограничена
высотой окна. Цвета используют существующие переменные темы Яндекс Музыки.

Renderer ожидает полные снимки состояния (не частичные обновления):

| Поле | Значение для UI |
| --- | --- |
| `participants` | Массив `{ participantId, role, connected }`; ID — непустая стабильная строка, роль — `leader` или `listener`, подключение — `true` / `false` |
| `selfParticipantId` | ID текущего пользователя из массива |
| `capacity` | Положительное целое число; ожидаемый лимит — 10 |
| `role` | Текущая роль пользователя для сводки «Ваша роль» |
| `code` | Код текущей комнаты |
| `status` | `idle`, `connecting`, `connected`, `reconnecting`, `ended` |
| `error`, `playbackError` | Необязательные коды ошибок подключения/команды и воспроизведения |

Неизвестные роли и состояния не подменяются известными. При переподключении собственная строка
показывает «Переподключается», другие — «Статус неизвестен»: последний снимок не подтверждает,
что участники всё ещё подключены. `connected: false` в актуальном снимке означает
«Временно отсутствует». Повторяющиеся ID отображаются один раз. Если `capacity` отсутствует,
показывается только известное число участников. Без `participants` остаётся старое представление
через `role` и `peerConnected`, без искусственного списка и выдуманной вместимости.

Старый обмен ролями через `swap` / `peerConnected` сохранён для старого формата состояния.
При наличии массива участников кнопка остаётся видимой, но отключена; рядом предусмотрено место
для будущего выбора адресата передачи управления (PR 4). Renderer не вызывает старую команду
для группового состояния: API передачи конкретному участнику в этом PR не добавляется.
`preload.cjs`, `main.cjs`, Sonata и синхронизация не меняются.

### Проверка UI

```powershell
node --test tests/MusicSync.Tests/*.test.cjs
```

Тесты запускают настоящий `renderer.js` в Node VM с небольшой DOM-фикстурой без внешних зависимостей.
Они проверяют состав 1/2/5/10, изменения участников и ролей, неизвестные статусы, старый контракт,
сохранение DOM-узлов/фокуса/прокрутки, повторную инъекцию, замену боковой панели,
экранирование, команды и открытие/закрытие. Фикстура не проверяет CSS и Electron.

На отдельной копии Яндекс Музыки **5.126.1** после подключения PR 1–2 вручную проверьте:

1. Состав 1, 2, 5 и 10 участников, код, копирование, счётчик и отказ во входе сверх лимита.
2. Приход, временное отключение, возврат и выход слушателя; изменение ведущего во входящем снимке.
3. Строку «Вы», одного ведущего, устойчивость временных имён, отсутствие дублей после обновлений.
4. Светлую и тёмную темы, маленькое окно, прокрутку 10 строк клавиатурой и мышью, доступность нижних кнопок.
5. Открытие клавиатурой, закрытие `Esc` с возвратом фокуса, закрытие снаружи, ввод кода без потери фокуса,
   переходы по разделам и повторное открытие панели.
6. Создание, вход, выход, ошибки подключения/воспроизведения и повтор синхронизации;
   старую смену ролей со старым агентом. С групповым агентом передача управления ожидает PR 4.

До появления PR 1–2 текущий агент продолжает использовать старый формат. Групповые данные
в автоматических проверках — только тестовые фикстуры; рабочий backend ими не заменяется.
