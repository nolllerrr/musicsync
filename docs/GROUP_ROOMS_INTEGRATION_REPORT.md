## Исправленные несовместимости

- Sync содержал v1-заглушку RoomMembership (пустой список, вместимость 2). Она заменена проекцией настоящего v2. Тестовые конструкторы обновлены. Дублирующий PublicParticipant и временный образец адаптера удалены; общий Participant используется сервером, клиентом и агентом.
- Leadership содержал только подготовительные контракты/чистую политику. Они подключены к RoomRegistry атомарно: создание, подтверждение, отмена, истечение, разрыв/замена соединения. Повышение ревизии и сброс истории/отчётов исключают старые команды после смены роли.
- Добавлен полный маршрут renderer → preload → main → AgentPipe → AgentSession → RoomConnection → сервер и обратно. Новый UI выбирает конкретного подключённого слушателя, показывает запрос только инициатору/адресату и использует явное подтверждение. Парная совместимость сохранена.
- Вместо 32 КиБ серверного кадра принят компактный контракт: Detail до 64 ASCII-символов машинного кода, вход 4096, выход 8192 байта с проверкой и при отправке. Предельный законный welcome с 10 отчётами, максимальными числами/ID и Transfer занимает 4220 байт.
- Рассылка на каждый отчёт заменена объединением по комнате с тиком 250 мс и подавлением неизменившихся отчётов. Команды/состав/роль рассылаются сразу. Детерминированный тест отправляет 200 обновлений от десяти мест и получает один актуальный снимок на получателя за flush, без заполнения очередей. Медленный клиент по-прежнему изолирован своей очередью/тайм-аутом.
- Глобальный предел по умолчанию теперь MaxRooms × Capacity + 16 (176), диапазон 2–1296. Compose задаёт 176/16/10. Реальный сетевой тест подтверждает 16 полных комнат и замену соединения при полной занятости.
- Отформатирована C#-база, включая несколько прежних отклонений в AsarPatch/SyncClock; добавлена проверка формата и build -warnaserror в PR workflow. Документация архитектуры, протокола, UI и синхронизации переписана по конечному поведению.

## Инварианты

Проверены один ведущий/до девяти слушателей, общий RoomState, уникальные публичные ID, непубликация токенов, запрет действий слушателя/старого ведущего, отклонение старой ревизии, сохранение места и ID при resume, независимый выход/обрыв слушателя, подтверждение выбранным адресатом, корректная смена ролей при гонках и истечении. Play/Pause, трек, перемотка, новый ведущий и завершение проверены через настоящий локальный сервер; медленные/неисправные плееры и отмена устаревшей загрузки/перемотки покрыты отдельно.

Grace ведущего не назначает нового ведущего автоматически. В комнате остаётся одно место с ролью ведущего, временно disconnected; при возврате оно сохраняется, при тайм-ауте комната завершается. Секретные токены живут только в памяти и приватном индексе сервера.
