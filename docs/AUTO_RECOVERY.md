# Восстановление после обновлений Яндекс Музыки

Функция включается пользователем в установщике. По умолчанию фоновых заданий нет. Она восстанавливает патч только для исходной пары EXE/ASAR, которая присутствует в проверенном каталоге сборок MusicSync и проходит проверку структуры и SHA-256.

## Почему внешний восстановитель

Обновление Яндекс Музыки может заменить весь `app.asar`, EXE и внедрённый загрузчик MusicSync. Поэтому проверка только из внедрённого Electron-кода не переживает обновление.

| Подход | Свойства | Решение |
| --- | --- | --- |
| Проверка только внутри ASAR | Исчезает вместе с патчем | Недостаточна |
| Постоянный процесс с таймером/наблюдателем файлов | Нужно поддерживать жизненный цикл, перезапуск и гонки обновления; постоянно занимает память | Избыточен |
| Windows Service | Установка службы и привилегии не нужны для каталога текущего пользователя | Не используется |
| Планировщик заданий Windows | Переживает перезагрузки и замену приложения; запускает короткую проверку от текущего пользователя | Выбран |

Создаётся задание `MusicSync-Recovery-<SID пользователя>-<ID каталога>`. В нём используются `InteractiveToken` и `LeastPrivilege`, вход текущего пользователя с задержкой в одну минуту и таймер раз в 15 минут. `IgnoreNew` исключает параллельные экземпляры от самого Планировщика; дополнительная файловая блокировка защищает от ручного запуска второго экземпляра. Ограничение длительности запуска — пять минут, автоматического перезапуска задания после ошибки нет. Пароль пользователя не сохраняется. Официальный механизм обновления Яндекс Музыки не изменяется.

XML соответствует [схеме Microsoft Task Scheduler](https://learn.microsoft.com/en-us/windows/win32/taskschd/task-scheduler-schema). Тест проверяет его присваиванием `XmlText` временному объекту `NewTask`; он не регистрирует задание на компьютере.

## Файлы вне Яндекс Музыки

В `%LOCALAPPDATA%\MusicSync\Recovery\<ID каталога>\` находятся:

- `MusicSync.Recovery-<SHA256>.exe` — копия опубликованного автономного установщика. Хеш проверяется при копировании и перед использованием. Она остаётся доступной, даже если официальный обновлятор заменил файлы Яндекс Музыки.
- `registration.json` — каталог приложения, имя и хеш восстановителя, добровольное включение функции.
- `attempts.json` — счётчики попыток для каждой пары «отпечаток приложения + сборка восстановителя», последнее диагностическое сообщение.
- `recovery.jsonl` — журнал UTC, статуса, отпечатка и результата. Одинаковые последовательные результаты не дублируются; после достижения 1 МиБ новые записи не добавляются.
- `recovery.lock` — временная эксклюзивная блокировка процесса.

Сохранение состояния использует запись во временный файл, `Flush(true)` и замену файла в том же каталоге. Счётчик попытки сохраняется **до** вызова установщика: аварийное завершение тоже расходует попытку. Максимум — три попытки для одного отпечатка и одной сборки восстановителя, включая повторный запуск Windows. Смена проверенной сборки приложения или обновление восстановителя получает собственный счётчик; возврат к прежним файлам не обнуляет старый счётчик. После исчерпания лимита нужна диагностика в установщике. Автоматическая проверка состояния продолжает выполняться без повторной установки.

Обновление MusicSync не скачивается восстановителем. Открытие нового автономного установщика и успешная ручная установка/восстановление обновляют внешнюю копию, если функция уже включена; таким образом она получает новый каталог совместимости. Переключение настройки также обновляет копию.

## Условия восстановления

1. Прочитать регистрацию и проверить внешний восстановитель.
2. Получить структурированную диагностику без изменения приложения.
3. Разрешить автоматическую установку только при `SupportedOriginal` или `PatchMissing`. Неизвестная версия, несовпадение SHA-256, повреждение, небезопасные пути и незавершённые операции требуют обновления MusicSync или ручной проверки.
4. Если Яндекс Музыка или её агент работают, отложить установку. Фоновой проверке запрещены закрытие приложения, принудительное завершение и автоматический запуск.
5. Сохранить номер попытки, захватить обычную блокировку установщика, повторно проверить исходные файлы и отсутствие работающего приложения, выполнить транзакцию установки. На время замены исходный EXE удерживается открытым для записи с разрешёнными чтением/переименованием: Windows не может создать из него новый процесс между заменами ASAR и EXE. Атомарная замена EXE последней делает пару согласованной. При ошибке после этой замены rollback сначала получает такой же барьер на новом EXE; уже запущенное приложение не завершается, а журнал сохраняется для явного восстановления.
6. Повторно проверить состояние `Installed` и записать результат.

Установщик остаётся ответственным за резервные копии, привязку журнала к исходной сборке, сверку хешей перед каждой заменой и rollback. Восстановитель не копирует старые резервные файлы самостоятельно. Неизвестные файлы и символические ссылки не обходятся и не удаляются. Адрес сервера берётся из проверенных сохранённых настроек.

## Отключение и удаление

При снятии флажка или удалении патча сначала сохраняется `Enabled=false`, затем удаляется задание Планировщика. Если Планировщик недоступен, сохранённая отмена всё равно запрещает фоновую установку; ошибку удаления задания установщик показывает пользователю. Исполняемый файл удаляется только при совпадении записанного SHA-256. Изменённые неизвестные файлы остаются для проверки. Выполняющаяся копия может остаться заблокированной до завершения процесса, но уже отключена.

История попыток и журнал сохраняются после отключения, чтобы переключение функции не обнуляло защиту от повторных неудачных установок. Пользовательские настройки Яндекс Музыки и endpoint MusicSync не удаляются.

## Команды

Из автономного опубликованного установщика:

```powershell
.\MusicSync-Together-<version>-Windows-x64.exe diagnose 'C:\Test\YandexMusic'
.\MusicSync-Together-<version>-Windows-x64.exe enable-recovery 'C:\Test\YandexMusic'
.\MusicSync-Together-<version>-Windows-x64.exe recover 'C:\Test\YandexMusic'
.\MusicSync-Together-<version>-Windows-x64.exe disable-recovery 'C:\Test\YandexMusic'
```

`diagnose` выводит JSON со строковым статусом и не создаёт файлы/задания. `recover` делает одну проверку; без предварительного добровольного включения ничего не устанавливает. `uninstall` отключает восстановление перед удалением патча. Если путь не указан, используется `%LOCALAPPDATA%\Programs\YandexMusic`.

Автоматические тесты используют временные каталоги, подменённый Планировщик и фикстуры EXE/ASAR. Регистрация настоящего задания и восстановление рабочей Яндекс Музыки в тестах не выполняются. Перед выпуском нужна ручная проверка включения/отключения задания обычным пользователем, запуска по таймеру и после входа в Windows, а также работы нового приложения и раздела «Вместе».
